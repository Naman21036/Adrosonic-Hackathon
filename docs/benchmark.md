# Benchmark results and provenance

The benchmark page deliberately separates actual evaluation metrics from simulated visualizations. A demo chart is not evidence of executed retrieval or system latency.

## Measured: 10-query matched-corpus evaluation

The Actual Results tab reads `reports/phase2/evaluation/ragas_matched_corpus.json`. It displays retrieval Hit@1/5/10 and MRR alongside RAGAS Context Precision/Recall for Dense, BM25, and Hybrid/RRF. The saved evaluation used 10 queries, RAGAS 0.2.15, and the configured Azure AI Foundry `gpt-4.1` judge. The queries were generated from indexed passage text; this result is not an official MS MARCO evaluation.

| Dense | 0.70 | 1.00 | 1.00 | 0.833 | 0.9539 | 1.0000 |
| BM25 | 0.40 | 0.80 | 0.90 | 0.582 | 0.6733 | 0.8400 |
| Hybrid/RRF | 0.70 | 0.90 | 1.00 | 0.814 | 0.9543 | 0.9400 |

## Simulated: 100-query dashboard visualization

The Demo tab loads `reports/demo/benchmark_100_simulated.json`, generated by `scripts/generate_demo_benchmark.py`. It contains 100 fixed query IDs in each of three separate simulated mode datasets (Dense, BM25, Hybrid/RRF). Each row has a fixed-seed latency, stage timings, `status: "SIMULATED"`, and `executed: false`. Its mean, min, max, P50, P95, and P99 are computed only from those synthetic rows.

This fixture is not read from `benchmark_summary.json`, does not call the embedder or retrieval API, and is never written into actual benchmark, evaluation, health, or production metrics. The benchmark UI displays a persistent **DEMO / SIMULATED** badge and states that the workload was not executed.

Regenerate the fixture without executing any queries:

```powershell
.\venv\Scripts\python.exe scripts\generate_demo_benchmark.py
```

The fixed seed and omission of run timestamps make repeated output deterministic. The file keeps `query_count: 100` (100 unique query IDs) and `records_per_mode: 100` (300 query-mode observations total).

## Pending: a new actual benchmark

A future actual latency benchmark requires an intentional retrieval run against an available local index:

```powershell
.\venv\Scripts\python.exe -m app.benchmark --queries 100
```

That command executes real queries and writes under `reports/phase2/benchmarks/`. Do not run it to display or regenerate the simulated demo. The dashboard demo requires no running FastAPI service.

## Status vocabulary

- **Measured**: read from a completed run artifact with execution metadata and provenance.
- **Simulated**: deterministic fixture for a UI walkthrough; no retrieval request was executed.
- **Pending**: an actual run has not been initiated or completed, so no actual latency value is available.
